# 用例打桩与个人分支端到端方案

## 用户流程与范围

用户在测试用例列表选择一组用例，或在单条用例中启动打桩。工具读取用例及关联源码，生成桩点、各用例的启停说明和实际代码修改，在独立源码副本提交，展示差异后提供“推送个人分支”。用户在已有流水线选择该分支/提交出包、烧包；在同一页面记录构建链接、包标识和各用例的实际验证结果。

本功能不新增导出，不自动启动流水线或烧包，不改写分析 Run 的完成状态。生成、提交、推送和实测结果分别展示。

## 源码和多任务

- 每次打桩任务有独立 ID、源码副本和个人分支。对每个涉及仓库记录分析基线、实际选择的基线 SHA、最终修改提交、推送结果。
- 默认使用分析仓库对应的本地 Git 仓库；普通源码目录可以另外指定 Git 仓库映射。Git 仅为生成/推送代码的依赖，普通分析仍不需要 Git。
- 一个任务可选择多个仓库、多个用例。多个任务不共用可写检出目录。个人分支名包含任务 ID，正常推送，不强推。
- 修改采用 Agent 输出的精确文本替换或新文件内容。宿主只处理路径、原文匹配、文件写入、Git 提交/推送，不决定桩点语义。错误只影响当前打桩任务，不否决用例和分析结果。
- 生成使用所选基线的完整源码；提示 Agent 对照分析快照和已有桩点。如果基线变化，需根据当前源码重新定位并在说明中列出差异。

## 桩点与执行方案

分析 Agent 可在用例的可选 `instrumentation` 字段描述桩点；老用例没有该字段也可以按需生成。专门的打桩操作复用用户配置的外部执行器和模型，不重跑原分析任务。

生成结果含 `points`、`profiles`、`edits`、`summary`。`points` 描述注入位置、动作、作用对象、触发时机/次数、启停方式、命中观察、清理及已知依赖/互斥。`profiles` 对应所选用例，说明哪些桩如何开启及先后顺序。

优先复用产品已有调测入口。多个桩装在同一个包时默认关闭，按用例显式启用；有先后依赖时按业务阶段组合。若源码没有控制入口，Agent 实现最小可用入口并给出实际命令，不编造不存在的调测能力。保留产品原有错误处理，不通过直接改写预期结果伪造验证。

以下是设计示例，具体位置和命令由目标源码决定：

| 用例场景 | 桩点及执行方式 | 如何处理相互影响 |
| --- | --- | --- |
| 队列创建时资源申请失败 | 启用 A，只让目标队列的一次申请失败，观察释放和重试 | 本轮关闭正常 IO 路径上的 B；A 失败后本就不会进入 IO |
| 已建链状态下 IO 处理失败 | 关闭 A，重新建链后启用 B，下发目标 IO | 检查 B 实际命中，再判定业务结果 |
| 创建失败后的清理再次失败 | A 制造创建失败，C 在随后清理阶段触发 | A 与 C 属于同一组合用例，按依赖启用，不作为冲突拆开 |
| 同时验证两个产品基线 | 两个任务分别选定提交，各自生成分支和个人包 | 每条验证记录保存当次包与代码提交；后填新包不会改写旧记录 |

执行说明来自 Agent 对实际代码的分析；宿主不会宣称能够静态证明任意两个桩互不影响。实际命中作为验证记录的一部分，未触发单独标记。

## 实现位置

| 仓库 | 变更 |
| --- | --- |
| pangea-agent | 用例生成方法增加可选桩点说明，不扩大用例结构门禁 |
| dsh-pangea | 独立打桩存储、Git 副本/提交/推送、外部 Agent 执行、HTTP 接口、用例页面组件、验证记录 |
| pangea-desktop | 分支构建固定本次两个组件提交，随产品打包 |

运行记录保存在当前 data root 的 `.pangea/fault-injection/<run_id>/<id>/`。源码、生成输出和任务记录都属于该任务；原 `repositories/` 和冻结分析产物只读。页面关闭后任务继续，重新打开可查看；进程中断的任务显示中断并可重新生成，不冒充已完成。

## 验证

使用真实临时 Git 仓库与 bare 远端验证选用例、生成替换、新文件、提交、推送、重新读取和实测记录。用小型 C 程序编译验证全关闭、A/B 单独触发、A/B 组合时的路径和次数。验证并行任务互不污染、精确提交推送、部分仓库推送失败可重试、取消和生成错误可见，以及路径越界不会写入。通过替身 Agent 验证协议和宿主链路；真实内网 Agent、流水线及设备烧包验收单独记录，不把替身执行冒充内网实测。

## 使用入口

测试用例列表选中用例后，在下方“打桩与个人分支”打开工作区；单条用例详情也有同一入口。执行器和模型默认取当前 Run 的配置；源码仓库可逐个选择并映射本地 Git 根目录，基线默认取分析记录的提交。生成结束后展开仓库差异，点击“推送个人分支”。“构建包与验证记录”保存包、构建链接、桩点实际命中和业务验证结论；“目标故障未触发”独立于产品验证失败。

失败的生成保留已选用例、源码副本和 Agent 原始输出；重新生成产生新任务，不把半成品当作完整修改推送。已完成的多仓库提交在推送失败后可以重试，只补推尚未成功的仓库。运行时新增的格式检查仅检查本次写代码需要的仓库、编号、执行说明和文本替换，不评价用例语义，不影响原分析提交。

- `npm test`：companion 的构建、语法与测试套件执行成功；其中环境条件不满足的既有测试保持跳过。
