# 固定个人分支打桩改造与验收

日期：2026-11-16。修改位于 dsh-pangea 的本地 langgraph 工作区，未推送。本记录替代上轮涉及任务分支和自动生成提交的结论。

## 最终行为

- 项目“代码仓库与构建”保存已有个人开发分支和推送远端；任务不能覆盖这两个目标或源码路径，不再使用 branch_prefix。
- 独立代码打桩页面：选择分析任务 → 多选用例并查看桩点 → 设置与生成。生成后查看实际差异，再点击“提交并推送到 A”。
- 生成使用个人分支和同名远端分支的可快进最新代码；分析快照只提供用例来源。分叉、缺失分支、缺失远端会提示失败，不创建任务分支。
- 生成阶段使用 detached HEAD 副本，只保存暂存差异，不创建提交，不改变原开发分支。
- 提交时重新检查项目配置、本地和远端提交、差异完整性及原工作区冲突。同一分支的提交串行执行，并用 Git 公共目录中的锁文件阻止另一进程并发写入。
- 本地分支发布显式指定 refs/heads/A，采用临时 receive.denyCurrentBranch=updateInstead 设置；不持久修改 Git 配置、不强推、不重置、不自动 stash。
- 已有未推送提交显示实际数量，确认绑定具体生成依据提交。后续分支变化要求重新生成。
- 提交成功但推送失败可重试同一提交。提交命令完成与任务保存之间发生中断时，按父提交、任务提交信息和完整差异恢复提交号。
- 历史任务分支结果仍可阅读，但不能继续推送，需按项目配置重新生成。

新增重点用例覆盖：
1. 连续两次提交只推进 A，保留第一次修改，前后本地及远端分支列表一致。
2. 任务请求伪造分支、源码路径和旧基线不能覆盖项目配置。
3. 已有未推送提交必须确认对应代码版本。
4. 本地和远端分支在生成后变化，旧修改不能直接提交。
5. 远端可快进时以远端最新代码生成。
6. 同文件未提交内容不被覆盖。
7. 并发提交串行执行，后执行的过期任务被拒绝。
8. 排队提交可停止，不必等待前一个任务完成。
9. 用户在检查后切换到 B，提交仍只更新 A，B 的提交和工作树不变。
10. 提交已完成但提交号未保存的中断，重试不产生重复提交。
11. 多仓库部分推送失败后只重试未完成仓库。

## 实际边界

- Git 的 updateInstead 在开发工作树存在已跟踪文件的未提交修改时可能拒绝更新，即使该文件不在本次打桩差异中。原内容和已生成结果保留，用户处理后重试；不自动收纳或丢弃修改。
- 多仓库提交不是跨仓库原子事务，逐仓记录成功与失败。
- 模型使用确定性测试夹具，业务桩点语义、真实构建流水线和设备验证不在此次自动化通过范围。
- Windows 专属和缺少运行时的 33 项测试跳过，不计为通过。
- Chromium 因当前环境禁止 socket 启动失败；备用 headless-shell 下载也失败。没有截图验收证据，不能宣称视觉布局验收完成。
- Windows 长路径故障与 212 个文件差异的现场根因仍待内网只读取证；未改长路径和快照比较算法。
- 未构建正式 Windows 包，未推送到远端开发仓。
