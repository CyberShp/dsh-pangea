# 远端导入、打桩模型与交付错误修复

## 产品行为

- 远端导入先读取服务器 heads，再选择分析分支。分支检出建立本地跟踪分支；显式 tag/commit 的既有 API 导入仍保留 detached 分析行为。
- 导入前使用临时克隆，HEAD/index/工作区一致后发布。空 index 不会被自动 reset 到用户已有仓库。
- 配置面板分开显示本地个人分支、remote 和远端目标分支；支持远端刷新和创建本地跟踪分支。只改流水线地址不重新校验分支。
- 默认跳过 LFS smudge，提供按范围 pull。快照只将与指针 SHA256、size 严格匹配的真身视为等价，其他变化保留。打桩拒绝编辑 LFS 属性文件。子模块不隐式递归下载。
- 重导先建立并验证新副本，保留旧目录和 settings；未提交内容、本地独有提交会阻止替换。目录交换失败尝试恢复，崩溃留下的恢复记录在仓库列表读取时处理。备份不会自动删除。
- 导入、配置、LFS、重导与打桩准备/推送使用仓库事务锁；打桩模型生成使用独立副本，可并发。导入支持停止，并注册 Desktop 升级停止参与者。
- 本地分支和远端分支可以不同名，推进非当前本地分支不会切换用户工作区。推送连接中断保留提交；重试先核验远端是否已包含该提交。
- 缺结果文件显示“未交付”，解析错误保留底层信息；正常交付、取消与 dispose 路径不变。
- 打桩复用分析的模型目录读取/就绪判定；新任务在创建前校验收据。历史 retry 执行非收据校验，不自动换模型。

## 验证

Linux 本地：companion npm test 1060 通过、33 跳过、0 失败（1093 项）；新增/调整测试覆盖远端 heads、本地跟踪分支、分支映射、连续推送、推送结果对账、空 index、LFS 等价、重导和中断恢复、事务取消、模型收据和缺失结果。

React DOM：`node tests/fault-injection-model-dom.mjs`、`node tests/repository-settings-dom.mjs`。前者验证模型下拉、切换执行器、目录失败/为空禁用以及收据 payload；后者通过真实路由/Git 验证配置保存和重开。

模型、服务器和 Windows 原生环境的边界：真实 Git 测试使用本地裸仓库；模型为测试替身。企业 CodeHub SSH/GCM、LFS 网关故障、Windows 文件占用与长路径仍需 Windows test 成品验证。

## Issue 02：未声称修复上游

本轮可读到的 dsh-subagent-acp 实现将 end_turn 映射为 completed。内部 session.error 是否在现场通过 ACP 通知传给宿主，缺少原始协议记录；CodeAgent CLI 内部源码不属于本次两个仓库。

因此没有伪造 ACP error 枚举、没有把所有 end_turn 降级，也没有根据缺文件猜测“连接失败”。宿主未交付诊断是独立防线；CLI 正确拒绝失败 session/prompt 的修复仍待 CodeAgent 团队及真实协议复验。

## 推送边界

保留普通快进推送，不创建任务分支，不自动合并/强推。检查与推送之间目标分支被外部删除的竞争窗口需要服务端规则约束；本轮未声称普通 push 能原子保证“远端分支必须始终存在”。
