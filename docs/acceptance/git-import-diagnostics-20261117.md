# Git 导入失败诊断与下载复用

URL 导入在克隆完成后检出或校验失败，过去只返回“索引或工作区不完整”，并删除暂存仓库。本次改为显示具体差异、保存诊断并保留下载，使用相同地址、分支与仓库名称重试时复用该下载。

- 校验分别读取 HEAD tree、index tree 和 NUL 分隔的工作区状态。错误展示前 6 项路径与类别，诊断保留总数及前 100 项，包括重命名前后路径。
- `.pangea/repository-imports/` 保存每次相同请求的最新状态、阶段、LFS 跳过配置和失败 Git 命令的子命令、退出码、信号、耗时。记录不保存完整命令参数、凭据或环境变量。
- 克隆完成后的失败暂存不删除、不列入已导入仓库，不令首次导入失败的工作区跳过初始化。缺失或损坏的认领记录不会触发目录删除。
- 重试使用普通 checkout，不自动 reset、restore 或 clean 暂存中的修改。保留下载不等于修复所有检出问题；checkout 失败遗留的空索引或内容变化仍会被报告，修正后可离线复用。
- 正常本地目录复制、已有仓库拒绝覆盖、默认跳过 LFS、分支/标签导入保持原行为。本次未修改修复性重新导入或关联打桩仓库流程。

## 验证

Linux 本地真实 Git 及相关接口回归 49 项全部通过；前端产物已重新生成，修改文件语法检查与 diff 检查通过。新增 15 项覆盖具体差异、索引不一致、特殊字符重命名、LFS 跳过环境传递、失败下载留存、离线重试、请求隔离与认领记录保护。

已复现非 LFS 的相同错误形态：原始 CRLF blob 提交后新增 `text eol=lf` 属性而不归一化旧文件，clone/checkout 均成功，但工作区仍报修改。该用例验证诊断能力，不代表认定用户现场根因。未执行企业仓库或 Windows 原生复验。
