# 分析运行发布一致性问题报告

## 1. 复现与现象

- Run 在 Step 09 仍处于执行中时，正式 Markdown 报告已经落盘，但 `工作台投影.json` 尚未生成。概览随即显示“数据读取异常”和“结构化投影 broken”。
- Step 05、Step 07 已分别生成风险与测试设计 Markdown，但风险页和测试用例页在最终投影发布前持续显示 0 条。
- 首次尝试失败后点击“继续分析”，新的尝试覆盖当前状态，用户无法在概览中查看上一次失败原因。

## 2. 预期与实际

- 预期：运行中的阶段性文件写入不应被判为终态失败；实际：Reader 把“报告存在”当成最终交付应已完成的信号。
- 预期：已完成步骤的中间产物可作为未复核草稿展示；实际：页面只读取 Step 09 的工作台投影。
- 预期：继续分析后仍可追溯历史失败；实际：界面只呈现当前尝试。

## 3. 根因

1. `finalExpected` 将 `reportAvailable` 纳入终态判定。Step 09 的多个文件并非原子写入，报告先于投影出现时形成可复现的竞态窗口。
2. Reader 缺少活文档解析通道，风险和用例只能从最终工作台投影读取。
3. 客户端没有从任务的 `attempts` 中提取并呈现历史终态错误。

## 4. 修复

- 仅在 Run 已完成、Step 09 已完成、投影本身无效或发布状态明确为 broken 时判定投影失败；运行中缺少投影保持 pending/draft。
- Step 05 完成后解析风险清单与 SFMEA，Step 07 完成后解析测试设计和追溯矩阵，并以草稿状态展示；最终投影生成后自动切换为投影数据。
- 在概览中增加折叠的“上一次尝试失败”记录，保留失败原因和结束时间，不干扰当前尝试状态。

## 5. 验证

- 单元测试覆盖报告先落盘但投影尚未生成的 Step 09 窗口，断言发布状态不是 broken。
- 单元测试覆盖 Step 05/07 活文档解析，断言风险、用例及关联关系可读。
- 单元测试覆盖恢复运行后历史失败原因仍可访问。
- 插件完整测试通过：96 项通过，0 项失败。
- 真实 Run `dhcp-260906-01` 最终生成 15 条风险、20 条用例、10 个流程，质量结论 READY，验证通过。
