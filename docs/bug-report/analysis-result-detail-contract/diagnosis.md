# 分析结果详情契约诊断

## 现象

- 风险严重度筛选后列表为空，汇总指标与风险内容不一致。
- 风险和用例详情缺少说明、证据、关联关系、步骤及预期结果。
- 分析会话中可以写入讨论草稿，但输入区仍为只读，无法发送。

## 证据

- Run `dhcp-260906-01` 的最终投影包含 15 条风险、20 条用例和 9 条证据。
- 风险严重度实际使用 `P0/P1/P2`，客户端筛选使用 `Critical/High/Medium/Low`。
- 风险项提供 `narrative`、`evidence_ids`，客户端读取 `system_result`、`evidence`、`confidence`。
- 用例项主要提供编号、标题、优先级和关联风险，完整步骤仍在 `活文档/测试设计/*.md`。
- Reader 只验证顶层数组存在，未统一数组项契约。
- 分析会话由右侧过程面板设为只读；当前草稿插入函数仍把内容写入该会话。

## 根因

最终投影、活文档和客户端使用了不同的数据字段，Reader 没有在读取边界完成字段统一和关联解析。讨论入口也没有区分只读分析会话与可写讨论会话。

## 诊断策略

1. 用真实投影记录字段差异。
2. 用 Reader 测试复现严重度、证据和用例详情丢失。
3. 用客户端测试复现误导性摘要文案和只读会话选择。
4. 在 Reader 边界统一风险、用例、证据；客户端只消费统一结果。

## 超时策略

本次均为本地文件读取和前端纯逻辑，不新增网络等待、轮询或重试。

## 预警策略

投影无法提供的字段不显示占位判断；已存在的投影 ID 无法解析到活文档或证据时，在对应详情中明确显示缺少内容，不伪造结论。

## 用户可见交互修正

- 风险页改为风险概览，说明严重度和用例关联的统计口径。
- 风险与用例详情直接呈现分析说明、关联项和测试步骤。
- 讨论入口切换或创建可写讨论会话后再插入草稿。

## 验收

- Reader 回归覆盖最终投影与活文档合并：严重度、风险说明、证据反向关联、用例关联、前置条件、步骤和预期结果。
- Reader 回归覆盖续跑中的 Step 09：上一轮 `broken` 不再覆盖当前活动尝试；真实损坏投影仍保持告警。
- 客户端回归覆盖风险/用例文案、缺失元数据不渲染占位判断，以及只读分析会话到可写讨论会话的路由。
- 真实 Run `dhcp-260906-01` 验证结果：15 条风险、20 条用例、9 条证据；严重度分布为严重 5、高 9、中 1、低 0；抽样风险 RP-01 解析到 2 条证据和用例 TC-DHCP4-08 的完整步骤。
- 插件测试：`npm test`，100/100 通过。
- 桌面工程已更新组件 pin，并生成独立本地解包；打包后的 Cordis 分析启动集成测试通过。
