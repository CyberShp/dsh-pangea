# 创建分析后的导航与加载状态

## 诊断胶囊

- 现象：创建分析准备完成后跳回工作台，再进分析页短暂显示返回任务列表入口。
- 证据：独立 Dev 宿主端口 12155，监听 PID 103524，启动于 2026-09-09 01:25:44 +08:00；运行目录为 Desktop flow worktree 下的 `dist-dev/win-unpacked`。插件基线 d9c6093。
- 根因：startTask 切换会话但未指定页面；core 对新会话使用默认工作台；overview 将任务未加载与未选择混同。创建任务又使用 undefined Run 选择，允许准备期间回读旧会话的 Run。openPage 还会查找当前会话标签并将该 ID 用于另一会话。
- 诊断策略：复现新会话首次页面恢复、跨会话页面打开、任务请求未完成时的渲染，以及 task-create/task-start 请求期间的 Run 绑定。
- 超时策略：每个假设用定向测试验证，真实宿主仅使用独立合成任务。
- 预警策略：不修改用户原 profile，不停止用户分析任务；真实后端错误必须保留。
- 用户可见修正：分析准备和启动均留在分析页；数据加载期间明确显示加载状态。
- 验收：core 25/25、companion 160/160；真实 UI 创建合成分析并完成准备到运行的切换，持续停留任务详情，手动工作台往返未见错误返回入口。

## 报告人与复现

用户报告每次创建分析准备好后回到工作台，再进入分析页会短暂看到红色返回入口。期望新任务始终留在分析页，准备和加载过程使用正常状态提示。

回归测试分别复现了新会话被恢复到 `dsh-pangea:home`、跨会话激活旧标签、任务未加载时显示返回任务列表，以及新任务准备期间 Run 选择仍为 undefined。均先观察失败再修复。

## 修复

- 在既有 `registerProductSession` 上增加可选目标页面参数，分析相关会话在切换前登记 `analysis`，沿用原页面恢复机制。
- `openPage` 只在目标与当前会话相同时复用标签，跨会话使用目标 scope 打开页面。
- 新建任务在 Run 尚未绑定时明确选择 null；避免自动回读上一 Run。
- 尚未收到任务数据或请求仍在加载时显示“正在读取分析任务…”，真实接口失败继续显示错误。
